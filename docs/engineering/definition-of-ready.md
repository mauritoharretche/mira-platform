# Definition of Ready

A task is Ready only when:

- [ ] The user/problem and expected outcome are clear.
- [ ] Scope and explicit non-goals are written.
- [ ] Acceptance criteria are testable.
- [ ] Relevant domain rules and permissions are known or listed as open questions.
- [ ] Dependencies and external integrations are identified.
- [ ] Data, privacy and security impacts have been considered.
- [ ] UX/content requirements exist for user-facing work.
- [ ] Required ADRs are accepted or the task is explicitly an architecture investigation.
- [ ] A test and verification approach is defined.
- [ ] The task is small enough to review; otherwise it is split.
